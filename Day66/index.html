What I Learned
🪣

S3 Static Website Hosting

Enabled bucket-level static hosting, set index.html as the root document, and configured an error page. Public access blocked — CloudFront is the only entry point.

☁️

CloudFront Distribution

Created a distribution pointing to the S3 REST endpoint. Configured TTL cache policies, compress objects automatically, and enforced HTTPS redirect on all HTTP requests.

🔐

Origin Access Control (OAC)

Replaced legacy OAI with the modern OAC method. S3 bucket policy grants s3:GetObject only to the CloudFront service principal — bucket stays fully private.

⚡

Cache Behaviour & TTL

Configured separate cache behaviours: static assets (CSS/JS/images) at max TTL 31536000s, HTML at TTL 0 for fresh content. Invalidation via /* on every deploy.

🌍

Edge Locations & PoPs

CloudFront serves cached content from 450+ Points of Presence globally. Mumbai PoP ensures sub-50ms delivery to Indian users without hitting the S3 origin every request.

📋

Custom Domain + ACM SSL

Provisioned a free TLS certificate via AWS Certificate Manager (ACM), attached it to the distribution, and configured the CNAME in Route 53 for a custom domain over HTTPS.

Setup Steps
01

Create & Configure S3 Bucket

Create bucket in ap-south-1. Disable "Block all public access" toggle. Enable static website hosting, set index document to index.html. Upload site files.

02

Create CloudFront Distribution

Origin domain → S3 REST endpoint (not the website endpoint). Set Origin Access Control. Set default root object to index.html. Enable compression.

03

Attach OAC Bucket Policy

CloudFront auto-generates an S3 bucket policy. Copy and attach it — grants s3:GetObject to cloudfront.amazonaws.com service principal with your distribution ARN as condition.

04

Configure Cache Policies

Attach CachingOptimized managed policy for static assets. Create custom policy for HTML with TTL 0. Set price class to "Use North America, Europe, Asia" for cost control.

05

Verify & Invalidate Cache

Access via CloudFront domain (xxxx.cloudfront.net). Check X-Cache: Hit from cloudfront response header. On updates, run invalidation on /* path.

CLI Commands Used
aws-cli — day66 deployment
# 1. Create S3 bucket
aws s3 mb s3://day66-devops-site --region ap-south-1

# 2. Upload site files
aws s3 sync ./dist/ s3://day66-devops-site --delete

# 3. Get CloudFront distribution ID
aws cloudfront list-distributions --query "DistributionList.Items[*].Id"
→ ["E3K7XAMPLE1234"]

# 4. Invalidate cache after update
aws cloudfront create-invalidation \
--distribution-id E3K7XAMPLE1234 \
--paths "/*"
→ InvalidationId: I3XAMPLE5678 | Status: InProgress

# 5. Verify cache headers
curl -I https://xxxx.cloudfront.net/index.html
