Deployment

Step-by-Step
Setup Guide

From zero to a live URL in 6 steps. Every configuration choice explained.

STEP 01
Create S3 Bucket
Create a new S3 bucket with a globally unique name. The bucket name becomes part of your website URL — choose it carefully.
aws s3 mb s3://your-site-name
STEP 02
Disable Block Public Access
By default, S3 blocks all public access. Navigate to Permissions → Block Public Access Settings and uncheck all four options to allow public reads.
Permissions → Unblock All
STEP 03
Enable Static Hosting
Under Properties → Static Website Hosting, enable it, set index.html as the index document and error.html as the error document.
Properties → Static Hosting → Enable
STEP 04
Attach Bucket Policy
Add a resource-based policy granting s3:GetObject permission to all principals (*). This is what makes your files publicly readable over HTTP.
"Effect": "Allow", "Principal": "*"
STEP 05
Upload Website Files
Upload your index.html, CSS, JS, and any image assets to the bucket root. Set the correct Content-Type metadata for each file type.
aws s3 sync ./site s3://your-site
STEP 06
Access Your Live URL
Copy the S3 website endpoint from Properties. Your site is now live at the public URL — no DNS, no servers, no configuration headaches.
bucket.s3-website-region.amazonaws.com
aws-cli — bash
$ aws s3 mb s3://day57-devops-site
make_bucket: day57-devops-site

$ aws s3 website s3://day57-devops-site --index-document index.html --error-document error.html

$ aws s3 sync ./website s3://day57-devops-site --acl public-read

Key Concepts

What I Learned
Today

🪣
S3 Bucket
A container for objects in S3. Globally unique name, region-specific. The root of all static hosting.
🔓
Bucket Policy
JSON resource policy controlling who can perform which actions on which S3 objects. Essential for public read access.
🌍
Static Hosting
S3 feature that serves files as a website over HTTP. Defines index and error documents. Free endpoint included.
🛡️
Block Public Access
Account-level and bucket-level safety toggle that overrides all public access grants — must be disabled for hosting.
📦
Object Storage
S3 stores files as flat objects with metadata — not a filesystem. Each object has a unique key (path) within a bucket.
⚡
Serverless Delivery
No EC2, no web server software, no OS patches. AWS manages all infrastructure. You pay only per GB stored and per request.
🔗
S3 Endpoint URL
Auto-generated URL in format: bucket.s3-website-region.amazonaws.com. Point a custom domain via Route 53 CNAME.
📋
Content-Type Header
S3 serves the exact Content-Type you set at upload. text/html for pages, text/css for styles, image/png for images.
