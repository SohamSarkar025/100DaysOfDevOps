## 🏗️ 1. The Observability Architecture

Before diving into the terminal, I studied the architecture of Prometheus. It operates on a **Pull Model**—it actively scrapes targets (like nodes and pods) for metrics, stores them in a Time-Series Database (TSDB), and allows visualization tools like Grafana to query this data.

## ✅ Key Takeaways for SREs

- **Helm is Powerful:** Deploying the entire Prometheus stack manually would require dozens of YAML files. Helm simplifies this into a single command.
- **Data Collection vs. Visualization:** Prometheus is the powerful backend engine that scrapes and stores time-series data, while Grafana is the beautiful frontend that makes sense of it.
- **The Power of PromQL:** Mastering PromQL is non-negotiable for writing effective alerts and custom dashboard panels.
- **Community Standards:** Using pre-built Grafana dashboards (like ID 3662) saves hours of work and aligns monitoring with industry best practices.
